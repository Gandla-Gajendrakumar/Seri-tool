# Open questions for the product owner (Phase 0)

> **Answered 2026-11-21:** the product owner accepted every recommendation below (Q-1 to Q-14).
> They are now requirements. Q-13 (moult humidity) and the stage values still need source checks and
> your sign-off before any change is applied.

Each question has my recommendation. Answering "go with your recommendation" is fine.
Questions **Q-1 to Q-7 affect phase 1 code**. The rest can wait until the phase named.

| # | Question | Why it matters | My recommendation |
|---|---|---|---|
| Q-1 | **How many phone numbers get alerts?** | Each extra number multiplies SMS cost and setup steps. | Up to 3 (farmer + family member + helper or extension officer). The first registered number is the "owner" who can add or remove the others. |
| Q-2 | **Daily SMS cap per number.** | Too low and a real long problem goes quiet. Too high and the farmer starts ignoring texts. | First alert of every event always goes. Up to **6 repeat texts per day per number** (3 hours of continuous trouble at one every 30 min), then one "limit reached" text. Recovery texts are always sent. |
| Q-3 | **How the tolerance applies.** Your chawki range is 27–28 °C with ±1 °C. Is the alarm band 26–29 °C (tolerance added to the range edges, my reading) or 27–28 °C? | Decides how often alarms fire. | 26–29 °C: tolerance widens the target range. |
| Q-4 | **Language on the screen and the printer.** Showing Telugu/Kannada/Hindi on the OLED and printer means pre-drawing every message as an image (cheap printers have no Indian fonts). This costs flash space, makes printing ~3× slower and uses more paper per line. | Farmer experience vs complexity. The brief says no setup step may need English, so the **screen** must be local-language. | Screen: all 4 languages (required by the brief). **Printer: all 4 languages as images**, since the printout is the farmer's record. Fallback if you want it simpler: printer in English + numbers, with icons (↑ ↓ ✓). |
| Q-5 | **Which MQTT server receives the data?** Your own server, a paid service (AWS IoT, HiveMQ Cloud, EMQX Cloud), or undecided? | Affects cost per device per month and the certificate setup. | Generic MQTT-over-TLS client now, tested against a local Mosquitto server in simulation. Pick the provider before field trials. No dashboard in scope unless you ask. |
| Q-6 | **SMS command style.** English words like `STAGE 3` break the "no English" rule. | Farmer experience. | Digit-only codes printed on a card in each language, e.g. `11 3` = stage instar III, `12 2` = language Kannada, `20` = send status now. The device replies in the farmer's language to confirm. |
| Q-7 | **How is Wi-Fi set up without a smartphone or English?** Typing a Wi-Fi password with 3 buttons is slow but possible. | Many farmers will have no Wi-Fi at all. | (a) Cellular works with no setup at all, so Wi-Fi is optional. (b) The installer can send Wi-Fi details by SMS from the owner number (`30 <name> <password>`). (c) Button entry exists as a last resort. |
| Q-8 | **Battery runtime target during a power cut.** | Sets the battery size (cost) and how aggressively we save power. Rural cuts can last 8–12 h. | ≥ 24 h on the fitted 2-cell (~5,000 mAh) pack. Phase 4 reports the real figure. If it falls short, the 4-cell option is ready. |
| Q-9 | **Automatic stage advance?** Stage could advance by day count (e.g. instar IV after N days) with a confirm button. | Forgetting to change the stage gives wrong alarms. | V1: manual only, but the device beeps and asks "still chawki?" after the typical stage length. *(Phase 1, but small.)* |
| Q-10 | **Is commercial sale planned for V1?** Selling needs BIS registration for the adapter, possibly WPC approval for radios, and labelling. | Scope and cost. | V1 = pilot units only. Use a BIS-registered 12 V adapter and certified modules so the carrier board stays low-voltage. Certification work comes later. *(Phase 5.)* |
| Q-11 | **Which SIM operator?** Jio is LTE-only. SMS on Jio needs IMS support in the modem, and there is no GSM fallback. Airtel and Vi still have 2G. | Whether SMS works at all on a given SIM. | Recommend **Airtel or Vi** for pilots. I'll check A7670C band support against its datasheet in phase 4, but only the bench test proves Jio SMS. *(Phase 4/7.)* |
| Q-12 | **Do you have any real shed logs** (temperature/RH from a rearing cycle)? | Phase 3 replay is more convincing with real data. | If not, I'll generate a realistic 28-day cycle from typical Karnataka / Andhra climate plus shed effects (heater, wet gunny bags, night drop). Synthetic data will be clearly labelled. *(Phase 3.)* |
| Q-13 | **Moulting periods.** Sericulture guidance often calls for *lower* humidity during moults, which our fixed per-stage RH bands would flag as an alarm. | Possible false alarms twice per instar. | Look this up with the stage-profile research in phase 1. If confirmed, add an optional "moult" mode with its own band. Shown to you before applying. |
| Q-14 | **Printer model.** Many cheap 58 mm TTL panel printers only *receive* data and cannot report "paper out". | The paper-out alert requirement. | Choose a printer with a TX status line (e.g. CSN-A2 / EM5820 class). I'll confirm from datasheets in phase 4. If none is affordable, add a cheap paper-sensor switch. *(Phase 4/5.)* |
